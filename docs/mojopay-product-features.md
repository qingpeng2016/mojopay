# MojoPay 全球支付通道系统 · 产品功能

MojoPay 为商户提供统一的收款、换汇、结算和出款能力，商户服务端通过 OpenAPI 接入。资金由获准的上游账户体系执行收付与清算，MojoPay 的虚拟账本记录商户权益。 游戏商与其他行业商户使用相同的支付能力，商品、定价和履约由商户自行管理。技术实现见 [技术设计](mojopay-technical-design.md)。

优先级中，P0 为通道和资格验证，P1 为首期交易闭环，P2 为覆盖扩展，P3 为后续能力。支付方式按商户主体、国家、用途、币种、网络和签约权限开通。

## 1. 上游管理

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 上游及环境 | 新建和停用供应商，分别管理沙盒、生产和签约主体。Gate Pay 是首个参考上游 | P0 |
| 主账号和机构子账号 | 登记上游主账号，创建或同步子账号。跟踪开户状态、资金用途、权限、额度及余额。机构子账号与供员工登录的运营账号分开 | P0 |
| 凭据和回调 | 按环境及账号管理密钥引用、轮换、权限、回调状态和出款 IP 白名单 | P0 |
| 通道能力配置 | 管理按上游子账号和业务范围开通的收款、换汇、退款、划转、出款、订阅，记录允许地区、币种/网络、限额、费用及前端模式 | P0 |
| Gate Pay 能力验证 | 根据 [Gate Pay 资料](gate.pay) 验证动态地址、静态地址、Gate App/网页、法币收款、链上提现、机构划转、闪兑和回调。生产开通前逐项确认 PSP 授权、BTC 与法币兑换、子账号向下游银行账户出款 | P0 |
| 资金监控 | 查看上游余额、冻结与在途资金、流水、子账号划转记录和对账差异；支持通道临时停用与余额告警 | P1 |

## 2. 下游商户与账号管理

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 主账号和子账号 | 主账号代表签约商户，子账号可按店铺、品牌、业务线或地区开设。主账号管理员可汇总查询获授权的子账号 | P1 |
| 人员和隔离 | 配置管理员、运营、财务、审批人、开发者角色。子账号仅访问自身订单、资金、凭据和配置 | P1 |
| 多对多通道绑定 | 指定下游主账号或子账号接入哪个上游的哪个子账号。一个下游账号可绑定多个上游的多个子账号，分别授权用途、币种、额度、优先级和权重 | P1 |
| 合同及费率 | 配置商户费率、收费模式、限额、结算周期、准备金、可下发的通道能力和生效时间 | P1 |
| 收款人及受益账户 | 审核商户银行账户或链上地址，管理币种/网络、变更审批和停用。向最终用户代付需要独立授权 | P1 |
| 开放平台授权 | 由主账号为指定子账号开通 OpenAPI 接入权限，凭据、回调和联调见第 11 章 | P1 |

## 3. 资质进件与风控

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 商户 KYB | 核验经营主体、经营地区及类别、实际受益所有人、授权代表、资金来源和业务规模。按通道要求转交审批 | P1 |
| 最终用户 KYC | 商户可以传入其用户标识。按付款/收款方向、地区、交易金额和风险决定是否要求该用户 KYC，支持验证页面与状态回调 | P1 |
| 资格与审核 | 按主体、产品、地区、用途、通道和有效期记录审核范围，支持待补件、通过、拒绝、过期和复核 | P1 |
| 交易与链上风险 | 名单、地区、金额频率及渠道策略校验；按规则执行 KYT，必要时补充资金来源、收款人或 Travel Rule 信息 | P1 |
| 人工工单 | 风险交易和异常到账进入人工队列，冻结、解冻及大额放行记录审批人与证据引用 | P1 |

## 4. 通道路由、报价与换汇

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 可用通道筛选 | 检查商户绑定、身份验证、地区、方式、币种/网络、金额、额度、服务状态和资金清算可达性 | P1 |
| 指定通道和权重 | 可指定已授权通道，或按优先级及同级权重分配。权重决定订单笔数分配，一笔大额订单也按完整金额匹配通道 | P1 |
| 切换和解释 | 运营能查候选、排除原因及路由版本。付款指令已发出或原请求结果不明时，先查单及确认原尝试安全关闭 | P1 |
| 币种分离与报价 | 分别展示商品标价、付款币种、实收币种、结算币种及相关费用。报价有方向、汇率、有效期和保价条件 | P1 |
| BTC 收款结算法币 | 用户付 BTC，完成链上确认及风控后兑换，形成法币待结算款，按合格的法币出款链路结算 | P1 |
| 法币收款结算 BTC | 用户使用已开通的法币方式支付，上游资金可结算且符合拒付风控要求后换成 BTC，按授权链上出款 | P1 |
| 其他资产组合 | 同资产收付省略兑换；更多稳定币、链和法币按兑换、清算、出款的完整链路逐项上线 | P2 |

## 5. 收款与品牌收银台

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 商户建单与支付链接 | 商户通过 API 或后台生成支付订单及短期链接，查看可用方式、价格、有效期和支付状态 | P1 |
| 链上收款 | 支持 BTC 动态地址及二维码；配置链上确认要求，记录到账及交易凭证，处理错链、少付、多付和晚到 | P1 |
| Gate 账户支付 | 在已授权通道提供 Gate App 扫码、网页账户支付或 SDK 调起。自托管钱包使用实际开放的链上方式 | P1 |
| 法币本地方式 | 按通道审批开放银行卡、转账和本地方式。Gate 参考资料包括 Stripe、墨西哥 SPEI 及部分非洲本地方式 | P1 |
| MojoPay 与商户品牌 | 支持 MojoPay Logo 或商户 Logo，配置颜色、语言和返回地址。商户自有域名及高级白标按验收范围开放 | P1 / P2 |
| 上游托管页 | 上游要求采集卡资料、认证或授权时进入获准的上游页面。商户按签名 Webhook 或查单结果发货 | P1 |
| 静态地址、收款码及 POS | 提供可复用的地址或静态收款码，按地址、付款凭证和业务标识识别入账 | P3 |

## 6. 订单与资金异常管理

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 订单与交易查询 | 按商户、子账号、商户单号、平台订单号和时间追踪订单、上游尝试、实际到账、证据及时间线 | P1 |
| 到账异常 | 支持未付超时、晚到、少付、多付、错链、重复支付及回调缺失的处理，记录人工接纳或退款结果 | P1 |
| 单笔大额手工建单 | 财务填写一笔固定金额、付款方、合同或发票编号、用途、付款 / 结算币种和有效期；完成风控和审批后发出单次支付链接 | P1 |
| 大额审批与限额 | 按金额和风险补充材料，验证候选通道可完整承接。单笔限额不足交人工复核，原订单保留全部到账记录 | P1 |
| 退款 | 跟踪原支付、可退余额、累计部分退款、手续费及异步结果，按原渠道允许的方式退给原付款人 | P1 |
| 拒付与追偿 | 管理拒付、证据、准备金、商户通知和冲正。到账、退款、拒付及结算分别展示状态 | P1 / P2 |

## 7. 虚拟账本与资金管理

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 多币种虚拟余额 | 按商户账号和资产展示待结算、可用、冻结和在途。外部资产与真实资金位置以上游为准 | P1 |
| 分录和费用 | 追踪原支付、换汇、手续费、准备金、退款、冻结及出款凭证，财务调整经审批后使用冲正分录 | P1 |
| 上游资金划转 | 按实际资产位置和权限调拨资金；逐笔跟踪外部划转及在途状态。商户账本可汇总展示不同上游余额 | P1 |
| 风险隔离 | 商户子账号及币种独立记账，共用上游资金账户须符合签约权限并验证可独立分账 | P1 |

## 8. 结算与出款

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 结算计划与结算单 | 按子账号、资产和周期生成结算明细，显示手续费、准备金、退款抵扣、预计结算日和净额 | P1 |
| 商户提现 | 商户向审核通过的银行账户或链上地址申请付款；核验额度、审核、冻结余额，调用实际提供出款能力的上游 | P1 |
| 出款跟踪 | 查询上游单号、手续费内扣/外收、银行参考号或链上哈希。已确认失败解冻，结果不明继续冻结并查单，退回单独处理 | P1 |
| 受许可代付 | 商户可为最终收款人代付，按业务用途和收款人资质单独开通及风控 | P2 |
| 自动与批量结算 | 支持定期结算、批量出款、失败项单独追踪和逐笔对账 | P2 |

## 9. 对账、报表与运营后台

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 三方对账 | 对比业务订单、内部账本和上游流水，按上游子账号、币种、账单日追踪余额回算 | P1 |
| 差异和调整 | 识别缺单、重单、费用、汇率、状态与资金归属差异。差异关联凭证、冻结与处理工单 | P1 |
| 商户报表 | 下载结算单、收款及退款明细、费用、冻结和出款凭证；允许主账号按子账号汇总 | P1 |
| 开发者与运营支持 | 回调查询、人工重发、上游查单、通道启停、告警、审批轨迹及管理操作审计 | P1 |

## 10. 订阅与授权扣款

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 订阅计划及授权 | 支持固定周期扣款与用户授权后的主动扣款，记录计划、授予范围、撤销及生效条件 | P3 |
| 支持币种与页面 | Gate Pay 参考能力为 USDT、USDC，提供方托管收银台，网络及资质以上游实际开通为准 | P3 |
| 扣款跟踪 | 查订阅、续期、失败和取消；每期生成可对账订单并通知商户 | P3 |

## 11. 下游商户 OpenAPI

| 功能 | 操作与规则 | 优先级 |
| --- | --- | --- |
| 开发者接入 | 商户通过开发者文档及示例接入 `/openapi/v1`。沙盒和生产分别申请凭据、联调及开通权限 | P1 |
| API 凭据与权限 | 主账号管理员为获授权的商户账号创建、轮换及停用密钥，按接口能力分配读写权限。可配置来源 IP 白名单和每分钟请求配额 | P1 |
| 商户进件与用户实名 | 授权合作方可提交商户进件及开设子账号。商户可为本账号的最终用户发起 KYC 并查询进度 | P1 |
| 支付、退款与资金查询 | 查可用支付方式和报价，创建订单并获取收银台链接，查询订单、申请原单退款，查询余额、结算单及对账单 | P1 |
| 商户提现及代付 | 提现仅提交到已审核的收款账户。代付需单独开通，查询渠道受理、成功、失败或待确认状态 | P1 / P2 |
| 签名与幂等 | 商户服务端对请求签名。写请求使用幂等键；重试使用新的时间戳和随机数、沿用原业务幂等键。退款、出款重复请求只认原操作 | P1 |
| 商户 Webhook | 配置签名事件地址，订阅支付、KYC、退款、结算和出款事件。支持失败重试、查看投递记录及受控重发 | P1 |
| 联调与排障 | 以 `request_id` 查询请求结果、业务错误和响应耗时，支持按事件查每次回调投递。密钥、身份材料和完整收款账户资料不得出现在联调日志 | P1 |
